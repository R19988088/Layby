# 停放区出现动效

窗口从隐藏状态呼出时，玻璃、内容、按钮和阴影整体播放 420 ms 的弹出动画：前约 280 ms 从 38% 等比例放大到 106%，再用约 140 ms 直接缩回 100%。前 60 ms 同步淡入，让较小尺寸阶段更早可见。保留一次恢复，不再多次抖动。

实现位于 `ShelfWindowController.swift` 的 `ShelfSurfaceView.animateAppearance(reduceMotion:)`。Core Animation 仅改变呈现层的缩放与透明度，围绕窗口中心动画；不改变实际窗口尺寸、布局或文件接收区域。横向和纵向采用相同缩放比例，去除挤压、左右抖动及反复回弹。

行为约束：

- 摇晃、修饰键、刘海、快捷键及手动入口统一使用此效果。
- 已可见的窗口再次呼出时不重播。
- 动画开始前完成目标位置和布局；拖入接收无需等待动画结束。
- 关闭、拖动 header、切换展开尺寸时取消未完成的出现动画，立即回到正常比例。
- 开启“减少动态效果”时直接显示，动画过程中开启也会立即停止。
- 只移除本次出现动画，不干扰按钮悬停或蓝色边框呼吸。

动效的整体节奏、每阶段缩放比例及淡入时长均集中在上述方法中，可继续调整手感。实机视觉与真实拖入时机仍需在最新构建中验收。

## 跟随背景的深浅色

胶囊、堆叠、网格和列表共用同一个背景外观来源。macOS 26 的小尺寸原生玻璃会根据背后内容切换深浅色，大尺寸玻璃则可能保持系统外观。因此，在拖动条下方保留一个由主玻璃覆盖的胶囊尺寸原生采样面，将其 `contentView.effectiveAppearance` 同时应用到主玻璃和内容容器。采样位置始终跟随拖动条，移动窗口、吸附顶部和切换尺寸时保持同一锚点；由系统负责采样和切换时机，无需截屏权限或轮询。

`ShelfBackdropAppearanceView` 提供统一的外观来源；`ShelfGlassContentView` 接收原生外观变化并刷新已解析的背景颜色。主玻璃和内容仍保留独立的动画图层，避免拖动条跟随收起动画缩放，也避免文件内容被重复缩放。采样面不接收点击，不出现在辅助功能树中。

内容容器的 AppKit 外观继续传递到所有 SwiftUI 宿主，包括保留在后台的胶囊/浏览区、文件行与缩略图、服务按钮。文字、次级文字、按钮底色、选中状态、强调色和玻璃反光随之更新。文件图标与预览图保留原色。

拖动条使用深灰（浅色外观）或偏白浅灰（深色外观），提高默认可见度，并保留悬停伸长与拖动反馈。启用“减少透明度”后使用系统外观及对应的不透明背景；macOS 26 之前沿用原生磨砂玻璃并跟随系统深浅色。

验证包含 `ShelfAppearanceTests` 的跨模式外观传递、嵌套 SwiftUI 环境实时更新、重建内容后的继承及不透明背景刷新，并继续运行原有的动画、拖放和文件生命周期回归。真实背景集成测试可运行：

```sh
bash scripts/test-appearance.sh
```

此测试短暂打开专用黑白背景窗口，在测试应用自身的浅色和深色外观下检查三种布局及其胶囊状态，共 36 次背景切换；不改动系统主题或读取用户文件。需可访问桌面的 macOS 26+，并开启透明度。

原生外观继承依据：[Apple 的 AppKit Liquid Glass 说明](https://developer.apple.com/videos/play/wwdc2025/310/)、[NSGlassEffectView.contentView](https://developer.apple.com/documentation/appkit/nsglasseffectview/contentview)。
